- 시험 사진은 공개 데이터 출처이고 정답은 개발자가 붙였다. 실제 사용자 사진과는 다를 수 있다.

## 2. 입력 조건

같은 모델·같은 사진이어도 사진을 어떻게 넣느냐에 따라 1위 정답 수가 몇 장씩 달라진다. 그래서 숫자에는 조건을 붙인다.

| 조건 | 방법 | 쓰는 곳 |
|---|---|---|
| **앱 원본 입력** (대표) | 사용자가 올린 파일 그대로 `open_upright` → 분류. 앱(직접 추가·구매 후보)과 같은 경로 | 공식 숫자 |
| 품질 92 재저장 | 사진을 JPEG 품질 92로 한 번 다시 저장한 뒤 분류 (`scripts/prepare_dataset.py`가 학습 사진을 저장하는 방식과 같음) | 예전 기록과 비교할 때만 |
| 웹 체험판 | float16 가중치 + 브라우저 크기 조정. Python 결과와 다를 수 있다 | **아직 재지 않음** |

예전 기록(25.5% → 61.5% → 64.6% → 65.1%)은 품질 92 재저장 조건에서 세 지표(1위·상위 3개·대분류)까지 정확히 다시 나온다. 품질 90~95 중 세 모델 모두 92만 맞았다. 그래서 예전 평가가 이 조건이었다고 본다. 원래 평가 스크립트가 남아 있지 않아 이 부분은 **추정**이다.

- 33종이던 첫 모델(`a024a1d`)은 종류 수가 달라 같은 비교에 넣지 않는다.
- 지금 모델에서 두 조건 사이에 1위가 바뀐 사진은 4장이다 (레깅스 1, 맨투맨 2, 가디건 1). 상위 3개·대분류는 같다.
- 두 가지 불확실성을 따로 적는다.
  - 표본 크기: 192장이라 원본 122장의 95% 범위(Wilson)는 56.5~70.0%다.
  - 입력 조건: 저장 조건만 바꿔도(원본, 품질 90~95) 1위가 122~126장으로 움직인다.
- 재현: 서로 다른 두 환경(Linux / Windows, Python 3.13, torch 2.9.1, torchvision 0.24.1, Pillow 12.3.0)에서 4개 모델 × 7개 조건, 정답 수 84개가 모두 같았다 (2026-11-07).
- 검증 정확도 83.3%(클래스 평균 81.7%)는 가공한 검증 사진 기준이다. 원본 기준으로 다시 재지 않았다.
- 웹 체험판은 위 숫자와 다를 수 있다. 실제 브라우저에 192장을 넣어 재기 전에는 웹 정확도를 따로 말하지 않는다.

## 4. 숫자를 쓸 때

- 휴대폰 사진 정확도는 **앱 원본 입력 63.5% (상위 3개 88.5%, 대분류 92.2%)**를 대표로 쓴다. 예전 기록과 견줄 때만 "품질 92 재저장 기준 65.1%"를 조건과 함께 쓴다.
- 예전 기록 줄은 고치지 않고 이 표로 연결한다.
- 다시 재는 스크립트는 아직 저장소에 없다 (`TASKS.md` T-17). 만들면 데이터 커밋·파일 해시·모델 해시·라이브러리 버전·입력 조건을 결과와 함께 남긴다.
