# MVP 정의서 — AI 옷장

작성 기준: 2026-10-20, `main` 커밋 `1b1c6f1`

## 1. 서비스 한 줄

날씨·외출 목적·체질에 맞춰 **내 옷장 속 옷으로 코디를 추천**하고, 옷 사진을 올리면 **AI가 옷 종류를 자동으로 분류**하는 웹 서비스.

- 기본 사용자 가정: 외출 목적에 '등교'가 있는 것처럼 대학생을 기본으로 가정했다. 대상 사용자와 문제 정의는 `docs/problem.md`에서 확정한다 (아직 없음, `TASKS.md` T-10).

## 2. 핵심 사용자 흐름

```
가입·로그인 → 프로필(성별·체감 성향) → 옷 등록(스타터 30벌 또는 사진 + AI 분류)
  → 오늘의 추천(날씨·외출 목적 → TOP 3) → 코디 저장·피드백 → (다음 추천에 반영)
```

이 흐름이 공개 배포 주소에서 끝까지 되는 것이 MVP의 최소 조건이다.

## 3. 기능 범위

### Must (필수) — 모두 구현됨

| ID | 기능 | 상태 |
|---|---|---|
| M-1 | 이메일 가입·로그인·로그아웃, 사용자별 데이터 분리 (Supabase Auth + RLS) | 구현, 실제 프로젝트에서 시험 |
| M-2 | 프로필: 이름, 성별, 체감 성향(추위·더위 타는 정도) | 구현 |
| M-3 | 옷장 등록: 30개 스타터 옷장, 사진 등록 + 옷 종류 AI 분류(42종) + 대표색 추정 | 구현 |
| M-4 | 옷장 관리: 목록, 카테고리·계절·이름 필터, 비활성화, 삭제 | 구현 |
| M-5 | 날씨: 자동 조회(Open-Meteo, 도시 선택) 또는 수동 입력 | 구현 |
| M-6 | 코디 추천 TOP 3 (규칙 기반 점수) + 추천 이유 | 구현 |
| M-7 | 코디 저장, 👍/👎, 착용 후 피드백(체감·만족도·착용 여부), '별로' 조합은 다음 추천에서 제외 | 구현 |
| M-8 | KPI: 추천 세션 수, Top 3 수용률, 추천 로그 CSV | 구현 |

### Should (있으면 좋음)

| ID | 기능 | 상태 |
|---|---|---|
| S-1 | 일교차 안내: 귀가 시각까지 가장 추울 때 기준으로 겉옷 챙기기 안내 | 구현 |
| S-2 | 계절 분류: 옷마다 입는 계절 자동 계산, 직접 수정, 철 지난 옷 넣어두기/꺼내기 | 구현 |
| S-3 | 사기 전에 맞춰보기: 구매 후보를 지금 옷장과 맞춰 중복/코디 없음/빈 곳 채움/잘 어울림 판정 | 구현 |
| S-4 | 세탁 가이드: 소재별 안내 | 구현 |
| S-5 | 가상 착용(예시): 외부 공개 모델 CatVTON을 Hugging Face ZeroGPU Space에서 실행 | 코드 완료, Space 생성 대기 (T-07) |
| S-6 | 설치 없는 웹 체험판 (브라우저에서 추천·분류) | 코드 완료, GitHub Pages 켜기 대기 (T-04) |
| S-7 | 로컬 데이터를 공개 서비스 계정으로 옮기기 (`scripts/migrate_to_supabase.py`) | 구현 |
| S-8 | 로컬 모드: 설정 없이 PC에서 로그인 없이 실행 (SQLite) | 구현 (예전 방식 유지) |

### 제외 (이번 MVP에서 만들지 않음)

| 기능 | 제외 이유 |
|---|---|
| 새 상품 자동 추천 (쇼핑몰 상품 추천) | 범위 밖. 내 옷장 속 옷 추천에 집중 |
| FashionCLIP 등 추가 AI 모델 도입 | 확정되지 않은 기능, 임의로 범위에 넣지 않음 |
| 개인화 추천 모델 (학습형 추천) | 실제 사용자 반응 데이터가 아직 없음. 피드백을 모아 두고 나중에 검토 |
| 키·몸무게 기반 3D 아바타 | 사진 한 장으로 3D 옷을 만드는 것은 연구 수준이라 기간 내 어려움 |
| 유료 AI API (OpenAI·Google 가상 착용 등) | 비용, 사진 외부 전송 문제. 무료 서비스만 사용 |
| 광고·제휴 수수료·결제 등 수익화 | 비상업·학습·시연용 운영 |

### 알려진 제약 (MVP에 포함하지 않은 것)

- 비밀번호 찾기 메일 없음: Supabase 무료 기본 메일은 팀원 주소에만 시간당 2통이라, 가입 인증 메일도 끈 상태
- 가상 착용은 신발 미지원, 최대 2벌, 실제 사이즈·핏 미반영
- 무료 서비스라 잠들기·사용량 제한이 있음 (`DEPLOY.md` 5절)

## 4. 초기 성공 기준

| 구분 | 기준 | 현재 |
|---|---|---|
| 기능 | 공개 주소에서 핵심 흐름(가입→옷 등록→추천→저장)을 끝까지 수행 | 실제 Supabase + 로컬 앱으로 확인 (2026-10-17). 배포 주소에서 확인 필요 (T-01) |
| 데이터 분리 | 다른 계정의 옷장·기록·사진을 보거나 바꿀 수 없음 | 확인 (`docs/test-plan.md`) |
| 사용자 시험 | 실제 사용자 __명(팀 결정)이 도움 없이 핵심 흐름 완료 | 미실시 (T-09) |
| KPI | Top 3 수용률 __% 이상 (팀 결정) | 측정 전 |
| 분류 | 검증 정확도 80% 이상 유지 | 83.2% (검증 5,127장). 휴대폰 사진 시험 192장 61.5% |

`__` 칸은 팀이 정할 값이다. 정하면 `docs/problem.md`와 이 표를 함께 고친다.
