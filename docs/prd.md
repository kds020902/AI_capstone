# PRD (제품 요구사항) — AI 옷장

작성 기준: 2026-11-07 (추천 규칙 v2 반영), 처음 작성 2026-10-20. 범위는 `docs/mvp.md`, 구현 구조는 `docs/tech-spec.md`, 분류기 숫자의 조건은 `docs/evaluation.md`.

## 1. 화면 구성

| 화면 | 들어가는 조건 | 주요 동작 |
|---|---|---|
| 로그인 / 회원가입 | 공개 배포 모드에서 로그인 전 | 이메일·비밀번호로 가입 또는 로그인 |
| 홈 | 로그인 후 | 서비스 소개, 무료 서비스 안내 |
| 프로필 | 〃 | 이름·성별·체감 성향 저장과 수정 |
| 내 옷장 | 〃 | 탭 3개: 옷장 목록(정보 수정) / 30개 스타터 옷장 / 직접 추가(사진 1~10장) |
| 오늘의 추천 | 〃 | 날씨·외출 목적 → TOP 3, 저장·피드백 |
| 사기 전에 맞춰보기 | 〃 | 구매 후보 등록과 판정 |
| 저장 코디 | 〃 | 저장한 코디 다시 보기 |
| KPI·데이터 | 〃 | 추천 세션 수, Top 3 수용률, 로그 CSV |

메뉴는 사이드바에 있다 (휴대폰은 왼쪽 위 » 로 연다). 사이드바 아래에 로그인 이메일, 로그아웃, (설정 시) 웹 체험판 링크가 있다.
로컬 모드(설정 없음)에서는 로그인 화면 없이 사이드바에서 사용자를 고른다.

## 2. 기능 요구사항

### F-01 가입·로그인 (M-1)
- 회원가입: 이메일, 비밀번호(6자 이상), 비밀번호 확인. 이메일 인증을 끈 설정이면 가입 즉시 로그인된다.
- 로그인 상태는 브라우저 세션마다 따로 유지된다. 로그아웃하면 로그인 화면으로 돌아간다.
- **수용 기준**: 가입 → 메뉴가 보임 / 틀린 비밀번호는 거부 / 로그아웃 후 다시 로그인하면 내 데이터가 그대로 있음.

### F-02 프로필 (M-2)
- 이름, 성별(남성/여성), 체감 성향 5단계(추위를 잘 탐 ~ 더위를 잘 탐).
- 체감 성향은 입을 수 있는 옷 안에서 더 얇은 쪽·두꺼운 쪽을 고르는 데(최대 ±3℃) 쓰인다. 입을 수 있는 옷 자체(착용 기온 범위)는 바꾸지 않는다. 성별은 스타터 옷장 구성에 쓰인다.
- 공개 배포 모드에서는 계정당 프로필 1개. 프로필이 없으면 다른 화면에서 "프로필에서 내 정보를 먼저 저장해 주세요"(로컬 모드: "프로필에서 사용자를 먼저 만들어 주세요")를 안내한다.
- 체감 성향을 바꾸면 지난 추천은 비워진다.

### F-03 옷장 관리 (M-4, S-2)
- 목록: 사진, 이름, 대분류/세부분류, 두께(1~5), 입는 계절, 색상, 비 적합 여부, 소재별 세탁 안내.
- 필터: 카테고리, 계절, 이름·세부분류 검색.
- 비활성화(넣어 두기): 목록과 추천에서 빠지고 '넣어 둔 옷'에서 다시 꺼낼 수 있다.
- 삭제: 목록에서 숨긴다(소프트 삭제). 과거 추천 기록은 유지된다.
- 계절 정리: 지금 계절에 안 입는 옷을 한 번에 넣어 두고, 넣어 둔 옷 중 지금 계절 옷을 한 번에 꺼낸다. 옷마다 입는 계절을 직접 고칠 수 있다.
- 옷장을 바꾸면(추가·정보 수정·비활성화·다시 활성화·삭제·계절 정리·스타터 추가·구매 후보 '샀어요') 지난 추천은 비워진다. 지운 옷·넣어 둔 옷이 든 추천이 남아 저장되지 않게 하려는 것이다.
- 목록의 사진은 작은 사진(긴 변 480px)으로 보여 주고, 한 번 받은 사진은 그 세션 동안 다시 내려받지 않는다.

### F-04 스타터 옷장 (M-3)
- 프로필 성별 기준 캐주얼 옷 30벌을 한 번에 추가한다. 같은 이름이 이미 있으면 다시 넣지 않는다.

### F-05 사진으로 옷 등록 (직접 추가, 1~10장) + AI 분류 (M-3)
- '직접 추가' 탭에서 JPG/PNG를 한 번에 1~10장 올린다 (장당 최대 20MB). 10장을 넘기면 앞의 10장만 받고 알린다. 지금 확인 중인 사진과 같은 사진은 한 번만 넣는다.
- 올리면 사진마다 바로 AI 분류(42종 중 확률 높은 후보 3개와 확신도 %, 웹 체험판과 같음)와 대표색 추정을 하고, 이름을 '{색} {종류}'로 채운다 (옷장·다른 사진과 겹치면 뒤에 2, 3 …). 올리기 칸은 접힌다.
- 1등 확신이 70% 이상이면 "AI 판단: …", 미만이면 "AI가 확실하지 않아요 … 맞는 종류를 골라 주세요"로 안내한다. 어느 쪽이든 1등이 먼저 골라져 있고, 다른 후보나 '다른 종류'(42종 목록)를 고를 수 있다.
- 확인 카드: 사진 한 장과 그 옷의 정보(종류, 이름, 색, 대분류, 두께/보온, 설명, 더 보기: 소재·비 오는 날)를 함께 보여 준다. 노트북은 사진|정보 좌우, 휴대폰은 위아래. 카드 부분만 따로 스크롤해서 아래 버튼이 화면 안에 남는다 (스크롤 높이 = 화면 높이 − 460px, 최소 300px).
- 종류를 바꾸면 대분류·두께·비 적합이 규칙표 기본값으로 바뀌고, 종류나 색을 바꾸면 이름도 다시 지어진다. 이름을 직접 고치면 그 뒤로는 그대로 두고, 비우면 자동 이름으로 돌아간다.
- 여러 장일 때: 사진 옆 ‹ › 로 이전/다음 (1번에서 ‹ → 마지막, 마지막에서 › → 1번), [목록]을 누르면 1~N번 작은 사진·확인 여부가 나오고 번호를 눌러 바로 간다. [✓ 확인하고 다음 ›]은 이 사진을 '확인함'으로 두고 아직 확인 안 한 다음 사진으로 간다. [저장 (n장)]은 확인한 사진만 한 번에 저장하고, 확인한 사진이 없으면 꺼져 있다.
- 1장일 때: 목록·이동·[확인하고 다음]이 없고 [저장]이 바로 저장한다.
- 아래 버튼은 장수와 상관없이 [사진 빼기] [다시 올리기] [저장]. [다시 올리기]는 올리기 칸을 다시 열어 10장까지 더 넣거나(확인 상태는 그대로), 지금 사진을 모두 빼고 처음부터 올리게 한다.
- AI 기록(ai_category·ai_subcategory·ai_confidence)에는 사용자가 고른 것과 상관없이 AI 1등 답을 남긴다.
- 사진은 긴 변 1280px JPEG로 줄여 내 계정 폴더에만 저장한다 (공개 배포 모드. 로컬 모드는 원본을 `data/uploads`에). 같은 순간에 여러 장을 저장해도 파일 이름이 겹치지 않게 사진마다 앞에 `b0_`, `b1_` … 을 붙인다. 옷 정보는 한 번에 DB에 넣는다.
- 저장 후 정보 수정: '옷장 목록'의 옷 카드 [정보 수정] → 이름·종류·대분류·색·두께·소재·비 적합·설명을 고친다. 종류를 바꾸면 대분류가 따라온다. 사진·AI 기록·계절 설정은 그대로이고, 지운 옷은 고쳐지지 않는다. 설명이 있으면 카드에 보인다.

### F-06 날씨 (M-5, S-1)
- 자동 조회: 도시 8곳(인천·안양·서울·수원·대전·대구·광주·부산) 중 선택, 귀가 예정 시각(18/20/22/24시) 선택 → [현재 날씨 불러오기].
- 수동 입력: 기온, 체감온도, 습도, 강수량, 풍속, 비가 옴, 저녁 늦게까지 밖에 있어요 + 저녁 체감온도.
- 불러온 날씨는 도시와 함께 기억한다. 도시를 바꾸면 앞 도시 날씨로 추천하지 않고 "○○ 날씨를 불러온 상태예요… 다시 눌러 주세요"라고 안내한다 (그동안은 기본값 22℃·비 없음).

### F-07 코디 추천 (M-6)
- 외출 목적 4가지: 등교 / 데이트 / 운동 / 격식.
- [TOP 3 추천 생성] → 순위, 점수, 코디 구성, 추천 이유, 점수 근거.
- 결과 위에 "실제 체감 ○℃ · 추천 기준 ○℃"를 보여 준다 (운동이면 "+5℃", 체질·쌀쌀한 비를 반영했으면 두께 기준 온도도).
- 점수 차이가 2점(0.02) 안이면 색 조합이 더 잘 어울리는 코디를 앞에 둔다는 안내를 보여 준다 (그래서 1위 점수가 2위보다 조금 낮을 수 있다).
- 비즈니스 규칙은 3절.

### F-08 저장·피드백 (M-7)
- [이 코디 저장]: 같은 추천을 두 번 저장해도 1번만 저장된다. 저장하면 그 추천 세션이 '완료'로 기록된다.
- [👍 좋아요] / [👎 별로]: '별로'를 누른 조합은 다음 추천에서 빠진다.
- 착용 후 피드백: 체감(매우 추움 ~ 매우 더움), 코디 만족도(1~5), 실제로 착용함.

### F-09 사기 전에 맞춰보기 (S-3)
- 상품 사진(또는 캡처), 종류, 색, 두께/보온, 비 오는 날 부담 여부, 이름, 상품 링크(선택, 메모용)를 넣고 [구매 후보로 저장].
- 사진을 올리면 바로 AI 분류해 F-05와 같은 후보 3개·확신 안내를 보여 주고, 고른 후보가 '종류'에 들어간다.
- 판정은 3절 규칙. 계절(여름/봄·가을/겨울) × 목적 4가지 상황별 코디 예시를 보여 준다.

### F-10 저장 코디 / F-11 KPI·데이터 (M-8)
- 저장 코디: 저장한 추천을 다시 보여 준다.
- KPI: 추천 세션 수, Top 3 수용률 = 코디를 1개 이상 저장한 세션 ÷ 전체 추천 세션.
- 추천 로그 CSV 내려받기 (내 기록만).

### F-12 가상 착용(예시) (S-5)
- 버튼 표시 조건: 설정에 Space 주소가 있고, 옷이 상의·하의·원피스·아우터일 때 (신발 제외).
- 위치: 옷장 카드, 추천 결과, 구매 후보.
- 여러 벌이면 최대 2벌 선택. 기본은 상의(또는 원피스) + 하의. 입히는 순서는 하의가 마지막.
- [새 창(Hugging Face)에서 열기 · 권장]과 앱 안 창 두 가지. 옷 사진 주소는 10분짜리 서명 주소로 넘긴다.
- 사람 사진은 AI 옷장에 저장하지 않는다. 결과는 'AI가 그린 예시'이며 사이즈·핏 미반영이라고 표시한다.

### F-13 웹 체험판 (S-6)
- 설치·로그인 없이 브라우저에서 추천과 사진 분류. 날씨는 직접 입력, 옷장은 브라우저에 저장.
- 추천·분류·계절·구매 판정 결과가 앱(Python)과 같아야 한다.

## 3. 비즈니스 규칙

### 추천 (`core/recommender.py`, 후보 자격·온도 `core/eligibility.py`, 규칙표 `data/clothing_taxonomy.csv`)
1. **온도 세 가지**
   - 실제 체감 = 체감온도(없으면 기온).
   - 추천 기준 = 실제 체감, 실외 운동이면 +5℃. 옷의 착용 가능 기온 범위와 비교하는 값.
   - 두께 취향 = 추천 기준 + 체질(추위를 잘 탐 −3℃ ~ 더위를 잘 탐 +3℃) − 쌀쌀한 비(체감 22℃에서 0, 18℃ 이하면 1℃). 목표 두께를 정할 때만 쓴다.
2. **규칙표** 42종마다 대분류, 기본 보온값(1~5), 등록 기본값 '비 오는 날 부담이 적음', 착용 가능 기온 범위, 목적 **절대 금지**(`blocked_purposes`), 목적 **완화 가능**(`fallback_purposes`), **젖음 부담**(0 / 0.5 / 1, 긴 바지·두꺼운 옷 1, 반바지·반팔·바람막이 0), 비를 막는 겉옷 표시(바람막이)가 있다.
   - 절대 금지: 운동 = 셔츠·블라우스·스커트·원피스류·블레이저·코트·로퍼·샌들·슬리퍼·구두·힐·플랫슈즈 / 격식 = 민소매·기능성 티셔츠·반바지·샌들·슬리퍼.
   - 완화 가능: 예) 운동 + 스니커즈·청바지·니트, 격식 + 반팔·스니커즈, 데이트 + 기능성 티셔츠·러닝화·슬리퍼.
3. **후보 고르기**: 절대 금지는 어떤 경우에도 뺀다. 코디(상의+하의 또는 원피스, 신발, 필요하면 겉옷)가 나올 때까지 **정상 → 목적 완화 → 기온 완화 → 둘 다** 순으로 한 단계씩 넓히고, 코디가 나오는 첫 단계에서 멈춘다. 완화했으면 어느 옷 때문인지 경고한다. 같은 단계 안에서는 완화한 옷이 적은 코디를 앞에 둔다. 비 오는 날 바람막이는 실제 체감으로 봐도 범위 안이면 입을 수 있다.
4. 조합: 추천 기준 **12℃ 이하면 겉옷 필수**(맞는 겉옷이 없으면 경고하고 겉옷 없이 다시 찾음), **24℃ 이상이면 상의 겹쳐 입기 안 함**. 평소 피하는 쌍(예: 구두+조거팬츠)은 빼되, 그러면 코디가 하나도 안 남을 때만 경고 후 허용한다. 어떤 단계로도 코디가 안 나오면 "추천 없음"과 무엇이 없는지(예: "'운동'에 신을 수 있는 신발이 옷장에 없어요 (로퍼는 '운동'에 추천하지 않아요.)")를 알린다.
5. **점수**: 맑은 날 = 날씨 점수(코디 보온값과 두께 취향 온도의 목표 보온값 차이). 비 오는 날 = **0.7 × 날씨 + 0.3 × (1 − 젖음 부담)**. 젖음 부담 = 0.5 × 신발 + 0.3 × 하체(하의·원피스) + 0.2 × 가장 바깥 상체(겉옷 > 겹쳐 입은 바깥 상의 > 상의) — 실제로 비를 맞는 옷만 본다. 사용자가 '비 오는 날 부담이 적음'을 등록 기본값과 다르게 바꿨으면 그 체크와 맞는 가장 가까운 단계로 옮긴다(사용자 판단 우선). 0.7/0.3과 0.5/0.3/0.2는 실험값이다. 습도·풍속은 점수에 넣지 않는다.
6. **순위**: 점수를 0.0001 단위 정수로 바꿔 0.02 칸으로 묶고, 칸 → 색 조합 → 점수 → 고정 순서(같은 날 같은 사용자는 같은 결과, 날마다 동점 코디가 바뀜; 앱·웹 같은 값). 색은 점수에 더하지 않는다.
7. 비슷한 코디를 걸러 상위 3개(신발만 다른 코디 제외), 고른 뒤에는 원래 순위대로. '별로' 조합 제외(그러면 하나도 안 남을 때만 다시 포함).
8. 일교차: 귀가 전 가장 추울 때의 체감이 지금보다 3℃ 이상 낮고 보온이 0.35 넘게 모자라면 겉옷 챙기기를 안내한다. 자동 조회는 시간별 예보에서 찾고, 수동 입력과 웹 체험판은 직접 넣은 저녁 기온을 쓴다.

### 계절
- 옷 종류의 착용 가능 기온 범위가 여름 28℃ / 봄·가을 11·16℃ / 겨울 0℃를 포함하면 그 계절. 사용자가 고친 값이 우선한다.

### 구매 판정 (`core/shopping.py`)
- 판정 순서: **중복**(같은 종류·같은 색 옷이 이미 있음) → **코디 없음** → **빈 곳 채움**(어떤 상황에서 최고 점수가 0.05 이상 오르거나, 원래 없던 코디가 생김) → **잘 어울림**.

### 데이터 소유와 권한
- 모든 데이터는 계정 소유. 사용자는 자기 행·사진만 조회·추가·수정·삭제할 수 있다.
- 추천·저장 코디·피드백은 자기 추천 세션에만 붙일 수 있다.
